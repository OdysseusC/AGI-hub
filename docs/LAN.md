# 局域网 Hub 与本机管理

[简体中文](LAN.md) | [English](LAN.en.md)

每台电脑运行一个 Hub，原生助手继续使用本机 Client 和已有会话。局域网功能让明确配对的 Hub 交换共享助手目录与邮箱消息。Hub 不选择协作者，不调用模型，也不把网络回执当作助手完成工作。

## 开启与配对

配对和目录同步无需两台电脑手动校时。邀请是否过期由签发端保存的本地令牌有效期判定；请求方也对待确认请求设置本地有效期上限。

1. 在每台电脑按[安装说明](../INSTALL.md)安装并启动 Hub。打开各自的本机管理地址，默认是 `http://127.0.0.1:7331`，使用现有安装流程提供的本机管理密钥。管理 API 和原生 Client 仍只走 loopback。
2. 在管理页填写主机名称与局域网监听地址，例如 `192.168.1.20:7347`。开启“局域网连接”并保存。监听端口默认 `7347`，与管理端口分开；不要把管理监听改成局域网地址。填写 `0.0.0.0:7347` 时须选择网卡，管理层从该网卡取得用于公告和配对的实际 IPv4 地址。指定网卡不把 wildcard TCP 监听自动缩小到该网卡；需要限制 TCP 接收接口时，填写该网卡的具体地址。
3. 按需开启“自动发现”，明确选择网卡后保存。局域网连接与发现都默认关闭。第一版使用所选接口上的 IPv4 mDNS/DNS-SD，服务名为 `_agihub._tcp.local.`，UDP 端口 `5353`。所选接口必须启用、支持组播且具有 IPv4 地址。服务记录可以携带 IPv4 或 IPv6 地址；IPv6-only 网络尚无发现传输支持。
4. 一端生成五分钟有效的邀请，将其交给另一端。在另一端粘贴邀请，可填写对方的数字 IP 与端口，或使用邀请内的地址，提交请求。手动地址只改变连接位置，邀请中的 Hub 身份、公钥与证明仍须匹配。主机名和公网地址不支持；私网、链路本地地址和 RFC 6598 共享地址 `100.64.0.0/10` 可用，loopback 仅适合本机测试。未指定地址（如 `0.0.0.0`）只能用于监听，不能作为公告或连接目标。
5. 回到邀请方，核对请求中的 Hub ID、名称和地址后接受。发起方提交请求与邀请方确认共同建立配对。首次配对需要直接连通；无法直连时不能借另一台 Hub 的信任跳过配对。
6. 在两端明确共享需要协作的本机助手。共享要求 endpoint 已启用、已绑定真实原生会话且使用邮箱协议 1。只有已共享助手进入远端目录。

组播受网络策略阻挡时，可以保持发现关闭，直接交换邀请并填写地址。根据实际网络策略放行所选局域网 TCP 监听端口；只有需要发现时才使用 UDP `5353`。发现不扫描网段、端口或助手会话。

已建立的 Tailscale 等私有覆盖网可以使用其数字 IP 手动配对，`100.64.0.0/10` 无需改成其他地址；IPv6 ULA 私有地址也可用。先在系统中确认两端已能直接通信，再选用该覆盖网的具体监听地址与端口。Hub 不安装或配置覆盖网，不调整防火墙或网络权限，也不依赖 Tailscale；不要假设覆盖网会转发 mDNS，手动配对时可保持自动发现关闭。

关闭发现会发送撤销公告、停止搜索、清空发现候选；保留已有配对与已授权网络连接。关闭局域网连接会停止该传输，但保留持久身份和配对配置。“断开”操作会撤销所选 Hub 的配对信任，之后需要重新配对。

## 身份、目录与路由

Hub ID 是持久公钥导出的 64 位小写十六进制值；修改名称或 IP 不改变它。同名助手用 `<Hub ID>/<endpoint>` 区分，原生会话 ID 留在目标电脑的本机绑定内。

发现公告仅包含 Hub ID、名称、服务地址和协议版本，不包含助手目录、凭据、消息正文或会话记录。发现候选未经认证，不会自动配对。缓存会到期；收到 goodbye 后使用一秒宽限再移除。发现关闭后不再刷新候选。

管理页区分“已发现”“已配对”“在线”“经中继可达”和“离线”，数量始终是当前 Hub 的视角。已配对端交换带签名的目录和路由公告，目录仅包含明确共享的本机助手。

目录按接收方本地接收时间计算 **10 秒租期**，不依赖来源电脑的绝对时间。来源 Hub 为公告签署跨重启持久、单调递增的 `revision`，接收方保留已见版本的高水位；重复或更旧的中继版本不续租。首次见到的历史中继公告只能作为有界的路由提示，不能证明主机在线或建立配对信任。接收方高水位仅在本次运行期间保留，重启不恢复旧租期；重启后首次收到旧中继版本，也至多提供一次 10 秒路由提示。Hub 连接、有效目录和原生助手已接手仍是不同的证据。

数据传输使用 TLS 1.3 和固定的对端公钥，通过 HTTP keep-alive 复用长连接。优先使用可用直连；否则采用广度优先搜索，在有效邻居公告中选择较短路径。路径/已访问节点按 `maxHops = 8` 限制，防止循环，并随公告过期失效。这里没有延迟学习、动态权重或全网最优路径承诺。

中继只提供传输。来源消息签名须在目的端验证，目的端还会检查配对和本机共享范围。A 信任 B、B 信任 C，并不表示 A 信任 C；A 与 C 必须先建立各自的直接配对关系，后续才可在直连不可用时借 B 中继。

## Hub 上线与原生唤醒

本地管理页通过 Hub SSE 刷新网络状态。已配对电脑的上下线、有效成员目录或选定路径变化会通知；同一在线目录的租期、签名、revision 续约和成员顺序变化不再反复触发刷新。连接失败导致的离线也通知一次。发现候选、配置及业务投递仍有各自事件，不能把每个 SSE change 都当成一次上线。

同一局域网不等于获准互通；发现、配对、共享和原生接入分别判断。上线事件不自动生成业务邮件，也不广播唤醒所有模型。`connected` 只证明网络链路，不能证明用户已登录、Client 已恢复或原聊天开始了新轮次。

重启验收可在重启前发出一条有稳定 ID、期限和回报预算的授权请求。目标助手准备好自启动后执行一次正常重启，恢复时通过自己的固定身份 helper 显式发回 `reply/result`，携带本次 nonce 与实际启动、原生轮次证据。原入口 Client 从自己的邮箱取得消息后，才经已验证的原生通道唤醒或引导原聊天。`status` 默认仅记录，不唤醒模型；自动回信不是 Hub 的职责。

## 打开另一台电脑的管理页

**0.5.0** 增加默认关闭的远端管理授权。配对只建立 Hub 身份信任，共享助手只允许对应协作；两者都不授予管理权。要从电脑 A 管理电脑 B，两端都须运行支持此功能的版本，并且当前能够直接连接。

1. 在 **B 的本机管理页**，找到已配对的 A，选择“允许此主机管理本机”。该授权只允许 A 管理 B；不同时允许 B 管理 A，也不授权其他主机。
2. 在 **A 的本机管理页**，找到直连在线的 B，选择“打开远端管理”。新页面仍位于 A 的 loopback 地址，例如 `http://127.0.0.1:7331/remote/<B的Hub-ID>/`，展示 B 的状态。
3. 页面继续使用 A 的本机管理认证。不要把 B 的管理密钥复制到 A 或填入页面。A 的 Hub 经已有固定公钥、双向认证的 TLS 连接请求 B；B 的管理密钥只用于 B 内部的本机调用，不进入 LAN 请求、浏览器或响应。
4. 在 B 的本机页面选择“撤销此主机管理本机”即可撤销，后续请求和已复用连接都会重新检查授权。断开配对也会删除该授权，重新配对默认仍关闭；已经开始执行的管理操作不会因此回滚。

远端页面可查看状态、管理已有 Agent 的安装、绑定、启停、共享和协作语言，并修改目标电脑的[可选登录自启动](AUTOSTART.md)总开关及已登记 Client 选择。可执行路径和参数只能在目标本机用 CLI 登记；远端接口不读取任意私有配置文件，也不接受任意 URL、目标端点或文件路径作为代理地址。

首版不提供远端网络设置、邀请、配对或管理授权修改；这些操作须回目标电脑本机完成。远端看到的其他 Hub 目录只供查看，不能继续打开第三台 Hub。管理请求不经中继，不因“经中继可达”而启用；“打开远端管理”只在直连在线时可选。未获 B 单独授权时仍会被拒绝。

远端页面首次载入和操作提交后获取状态，其余使用“刷新”按钮，不接入远端 SSE，也不增加定时轮询。连接中断或响应不确定时先刷新核对实际状态，不自动重做管理操作。

## 跨机邮箱

固定身份程序沿用 `mail-send --file <绝对路径>`，消息的 `recipient` 使用目录返回的完整地址：

```json
{
  "id": "saved-lan-request-001",
  "recipient": "<64位小写十六进制Hub-ID>/codex",
  "kind": "request",
  "content": "在用户已授权范围内核验指定资料，并回复结论。",
  "origin_ref": "actual-human-request-reference",
  "max_messages": 16
}
```

替换占位 Hub ID 后才能提交。双方发送 endpoint 都必须明确共享，目的 Hub 必须已配对，目的 endpoint 必须在其有效共享目录中。传输绕行中继不会改变收件人或授权范围。

提交成功返回规范化的 `lan-…` 消息 ID 和 `correlation_id`。后续回复使用返回的关联 ID，`reply_to` 引用返回的消息 ID；不要把原始本机 `id` 误当作跨机规范 ID。重传保留原提交文件与 ID，先核对状态；同 ID 同内容幂等，同 ID 不同内容拒绝。

跨机消息的 Client 回执通过 `source_message_id` 保留原提交 ID，供核对映射。发给原生助手的消息只包含一份正文，不附带内部网络载荷与传输指纹，避免重复占用上下文。

邮箱联邦协议 1 的每个关联固定为两个 endpoint。`max_messages` 在开始时固定分配：最初发起方获得 `ceil(max_messages / 2)`，另一方获得 `floor(max_messages / 2)`。例如额度 5 分为 3 与 2；额度 16 分为 8 与 8。离线或并发发送不能复制额度，已耗尽的一方不能借用另一方的剩余额度。

同一关联的参与者、原入口引用、总额度和期限不可重写。联系第三个 endpoint 需要另一个已获用户授权的协作关联；不得通过新建关联、换 ID 或重置额度规避当前协作的耗尽限制。默认总额度为 16、期限为 30 分钟；总额度范围为 1–64，提交时期限必须在未来 24 小时内。用户业务消息的 `deadline` 仍按原有截止时间语义处理；目录使用本地租期不改变业务截止时间，也不消除时钟偏差对业务期限判断的影响。

`network_pending` 表示本机已经持久保存，正在等待网络投递；`remote_received` 只表示目的 Hub 持久接收。原生 Client 的领取、会话实际消费、工具执行和成果核验仍需各自证据。`used_messages` 是当前 Hub 已观察到的消息数，不能当作整个网络的实时一致计数。

取消邮箱关联只作用于本机。已经进入 mesh 队列或已经发出的消息仍可能继续；远端原生操作也不会因此被取消。不确定投递需要对账，不自动重做副作用。

本版传递消息与共享目录，不同步文件。正文中提到的远端路径仍属于来源电脑和工作区，不能直接按本机路径打开；需要文件时使用另行授权的交付方式。

## Agent 协作语言

本机 Agent 卡片提供 41 种常用语言及自定义语言标签，例如 `en`、`zh-Hans`、`nb`、`sr-Latn-RS`。Claude 默认英语，其他 Agent 默认 `auto`；中文始终可选。每个设置只管助手间的提示、必要背景和回复，不覆盖用户要求的最终答复语言或交付物语言。

保存后，Hub 更新该端点的 `communication_language`，并同步已登记的受管协作技能中的 `communication-policy.md`。仅同步未被手动修改的受管文件；同步结果和冲突显示在页面，配置保存与技能同步成功分别表示。未登记的平台不会被扫描或自动安装。运行中的 Agent 需重新读取规则，文件更新不代表原生会话已加载。

发送 Agent 每次新发送前读取最新成员目录，按目标的 `send_language` 翻译必要指令，再提交一份精简消息。Claude 参与时优先采用 Claude 的选择；两端均为 Claude 时采用收件方选择。其他情况先采用收件方明确选择，再采用发件方选择；均为 `auto` 时由 Agent 合理决定。远端设置会通过签名目录传播，存在目录刷新延迟；建议各 Hub 使用同一版本。

Hub 不翻译或检测正文语言，不增加模型调用。附件、代码、路径、标识符和原文引用保留；不要同时发送整段原文与译文。消息的 `communication_language` 记录提交时规则，之后改设置不会改写既有消息或相同 ID 重试。最终给人的回答按该用户明确指定的语言，未指定时沿用用户交流语言。实际模型是否遵循规则需原生验收，离线测试不证明翻译质量。

## 管理 API 与安装状态

以下为本机 loopback 管理入口，要求现有管理认证及 Host/Origin 校验。LAN 监听器不直接开放这组 HTTP API；单独授权的远端管理只使用固定 TLS RPC 及下方列出的允许操作。

| 接口 | 内容 |
| --- | --- |
| `GET /v1/manage` | 本机身份、开关、网卡、助手、候选、已配对主机、待确认请求及自启动摘要；不返回私钥、endpoint token 或 Client 启动参数 |
| `POST /v1/manage/settings` | `name`、`network_enabled`、`discovery_enabled`、`listen`、`interface` |
| `POST /v1/manage/agent` | `endpoint`、`action`；`enable` 可带真实 `session_id`，`language` 必须带 `communication_language`；其他操作为 `install`、`disable`、`share`、`unshare` |
| `POST /v1/manage/network` | `action` 为 `invite`、`pair`、`accept`、`disconnect`、`allow_management` 或 `revoke_management`；`pair` 使用 `invitation` 和可选 `address`；`accept` 的 `peer_id` 填待确认请求 ID，其余主机操作使用 Hub ID；管理授权只能在目标本机修改 |
| `POST /v1/manage/autostart` | `enabled` 与已登记 endpoint 数组 `clients`；只改变下次登录行为，不接收启动命令或立即启停进程 |
| `/remote/<Hub ID>/v1/...` | 本机管理认证后，经固定 TLS RPC 访问指定直接配对 Hub；只允许 GET `/v1/manage`、`/v1/state`，POST `/v1/manage/agent`、`/v1/manage/autostart`；请求与响应各限 1 MiB |

常规本机状态更新通过 SSE 展示，不唤醒模型；远端管理使用手动刷新。选择错误的网卡、启动 socket 失败或运行中发生传输错误时，发现状态会显示为关闭并保留错误；应用重启后发现网卡不存在，不应让原有本机邮箱失效。

“安装”按钮调用仓库固定的受管技能安装能力，适用于 Codex、WorkBuddy 和 Claude。它不安装或验证全部原生 Client、Claude 插件或 Grok Routine；后续独立 Client、私有配置和真实会话绑定按[各 Client 说明](CLIENTS.md)完成。安装文件、已绑定、Client 已连接和原生能力已验证是不同状态。安装、发现、配对、探活和路由都不调用模型。禁用 endpoint 不代表已运行的原生任务被取消。

## 数据与验证范围

数据目录内的 `network/identity.json`、`network/state.json` 和 `discovery.json` 分别保存私有主机身份、网络状态与发现偏好。远端管理授权独立保存于本机网络状态，不随邀请、目录或路由传播。不要将身份文件、邀请证明或私有配置复制进公开文档、仓库或日志。保留身份文件才能在重启后维持同一 Hub ID。

首次写入联邦消息会将本机追加日志 `state.jsonl` 的快照版本提升到 **4**。旧程序不能安全理解这些字段；升级前备份完整数据目录，需要回退时使用匹配版本的程序与完整备份，不能盲目把旧可执行文件指向升级后的目录。

内部 mesh 传输协议保持 **2**（由 0.4.0 引入），邮箱协议保持 **1**。远端管理要求两端都支持 0.5.0 新增的管理 RPC；旧版本的配对与邮箱支持不代表支持该操作。

离线测试使用临时目录、模拟原生 Client 和注入的发现 socket，覆盖协议解析、过期、启停、配对、目录、消息持久化、重放、防环及管理操作。开发验证可运行：

```text
go test ./internal/discovery ./internal/mesh ./internal/manager ./internal/app
node --test internal/app/web/dashboard.test.cjs
```

这些测试没有启动真实局域网发现，也不调用模型。0.5.0 远端管理已用临时目录和 loopback TLS 验证未授权拒绝、授权后访问、撤销、重配不继承、禁止中继及密钥不泄露；真实多电脑远端管理尚未验收。实际不同网卡、防火墙、组播策略、休眠恢复、登录自启动与原生助手新生命周期仍需在获授权的目标环境单独验收。既有本机原生验收或跨机邮箱验收不自动覆盖这些能力。

远端邮箱与兼容任务只展示最近 30 条有界预览，长正文与成果引用会截断；完整记录保留在目标电脑。历史增大不会要求把完整内容复制到浏览器。
