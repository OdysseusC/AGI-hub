# 局域网 Hub 与本机管理

[简体中文](LAN.md) | [English](LAN.en.md)

每台电脑运行一个 Hub，原生助手继续使用本机 Client 和已有会话。局域网功能让明确配对的 Hub 交换共享助手目录与邮箱消息。Hub 不选择协作者，不调用模型，也不把网络回执当作助手完成工作。

## 开启与配对

1. 在每台电脑按[安装说明](../INSTALL.md)安装并启动 Hub。打开各自的本机管理地址，默认是 `http://127.0.0.1:7331`，使用现有安装流程提供的本机管理密钥。管理 API 和原生 Client 仍只走 loopback。
2. 在管理页填写主机名称与局域网监听地址，例如 `192.168.1.20:7347`。开启“局域网连接”并保存。监听端口默认 `7347`，与管理端口分开；不要把管理监听改成局域网地址。填写 `0.0.0.0:7347` 时须选择网卡，管理层从该网卡取得用于公告和配对的实际 IPv4 地址。指定网卡不把 wildcard TCP 监听自动缩小到该网卡；需要限制 TCP 接收接口时，填写该网卡的具体地址。
3. 按需开启“自动发现”，明确选择网卡后保存。局域网连接与发现都默认关闭。第一版使用所选接口上的 IPv4 mDNS/DNS-SD，服务名为 `_agihub._tcp.local.`，UDP 端口 `5353`。所选接口必须启用、支持组播且具有 IPv4 地址。服务记录可以携带 IPv4 或 IPv6 地址；IPv6-only 网络尚无发现传输支持。
4. 一端生成五分钟有效的邀请，将其交给另一端。在另一端粘贴邀请，可填写对方的数字 IP 与端口，或使用邀请内的地址，提交请求。手动地址只改变连接位置，邀请中的 Hub 身份、公钥与证明仍须匹配。主机名和公网地址不支持；私网和链路本地地址可用于局域网，loopback 仅适合本机测试。
5. 回到邀请方，核对请求中的 Hub ID、名称和地址后接受。发起方提交请求与邀请方确认共同建立配对。首次配对需要直接连通；无法直连时不能借另一台 Hub 的信任跳过配对。
6. 在两端明确共享需要协作的本机助手。共享要求 endpoint 已启用、已绑定真实原生会话且使用邮箱协议 1。只有已共享助手进入远端目录。

组播受网络策略阻挡时，可以保持发现关闭，直接交换邀请并填写地址。根据实际网络策略放行所选局域网 TCP 监听端口；只有需要发现时才使用 UDP `5353`。发现不扫描网段、端口或助手会话。

关闭发现会发送撤销公告、停止搜索、清空发现候选；保留已有配对与已授权网络连接。关闭局域网连接会停止该传输，但保留持久身份和配对配置。“断开”操作会撤销所选 Hub 的配对信任，之后需要重新配对。

## 身份、目录与路由

Hub ID 是持久公钥导出的 64 位小写十六进制值；修改名称或 IP 不改变它。同名助手用 `<Hub ID>/<endpoint>` 区分，原生会话 ID 留在目标电脑的本机绑定内。

发现公告仅包含 Hub ID、名称、服务地址和协议版本，不包含助手目录、凭据、消息正文或会话记录。发现候选未经认证，不会自动配对。缓存会到期；收到 goodbye 后使用一秒宽限再移除。发现关闭后不再刷新候选。

管理页区分“已发现”“已配对”“在线”“经中继可达”和“离线”，数量始终是当前 Hub 的视角。已配对端交换带签名的目录和路由公告，目录仅包含明确共享的本机助手。

数据传输使用 TLS 1.3 和固定的对端公钥，通过 HTTP keep-alive 复用长连接。优先使用可用直连；否则采用广度优先搜索，在有效邻居公告中选择较短路径。路径/已访问节点按 `maxHops = 8` 限制，防止循环，并随公告过期失效。这里没有延迟学习、动态权重或全网最优路径承诺。

中继只提供传输。来源消息签名须在目的端验证，目的端还会检查配对和本机共享范围。A 信任 B、B 信任 C，并不表示 A 信任 C；A 与 C 必须先建立各自的直接配对关系，后续才可在直连不可用时借 B 中继。

## 跨机邮箱

固定身份程序沿用 `mail-send --file <绝对路径>`，消息的 `recipient` 使用目录返回的完整地址：

```json
{
  "id": "saved-lan-request-001",
  "recipient": "<64位小写十六进制Hub-ID>/codex",
  "kind": "request",
  "content": "在用户已授权范围内核验指定资料，并回复结论。",
  "origin_ref": "actual-human-request-reference",
  "max_messages": 16
}
```

替换占位 Hub ID 后才能提交。双方发送 endpoint 都必须明确共享，目的 Hub 必须已配对，目的 endpoint 必须在其有效共享目录中。传输绕行中继不会改变收件人或授权范围。

提交成功返回规范化的 `lan-…` 消息 ID 和 `correlation_id`。后续回复使用返回的关联 ID，`reply_to` 引用返回的消息 ID；不要把原始本机 `id` 误当作跨机规范 ID。重传保留原提交文件与 ID，先核对状态；同 ID 同内容幂等，同 ID 不同内容拒绝。

跨机消息的 Client 回执通过 `source_message_id` 保留原提交 ID，供核对映射。发给原生助手的消息只包含一份正文，不附带内部网络载荷与传输指纹，避免重复占用上下文。

邮箱联邦协议 1 的每个关联固定为两个 endpoint。`max_messages` 在开始时固定分配：最初发起方获得 `ceil(max_messages / 2)`，另一方获得 `floor(max_messages / 2)`。例如额度 5 分为 3 与 2；额度 16 分为 8 与 8。离线或并发发送不能复制额度，已耗尽的一方不能借用另一方的剩余额度。

同一关联的参与者、原入口引用、总额度和期限不可重写。联系第三个 endpoint 需要另一个已获用户授权的协作关联；不得通过新建关联、换 ID 或重置额度规避当前协作的耗尽限制。默认总额度为 16、期限为 30 分钟；总额度范围为 1–64，提交时期限必须在未来 24 小时内。

`network_pending` 表示本机已经持久保存，正在等待网络投递；`remote_received` 只表示目的 Hub 持久接收。原生 Client 的领取、会话实际消费、工具执行和成果核验仍需各自证据。`used_messages` 是当前 Hub 已观察到的消息数，不能当作整个网络的实时一致计数。

取消邮箱关联只作用于本机。已经进入 mesh 队列或已经发出的消息仍可能继续；远端原生操作也不会因此被取消。不确定投递需要对账，不自动重做副作用。

本版传递消息与共享目录，不同步文件。正文中提到的远端路径仍属于来源电脑和工作区，不能直接按本机路径打开；需要文件时使用另行授权的交付方式。

## 管理 API 与安装状态

以下接口都在本机 loopback 管理监听器上，要求现有管理认证及 Host/Origin 校验。它们不在 LAN 监听器上开放。

| 接口 | 内容 |
| --- | --- |
| `GET /v1/manage` | 本机身份、开关、网卡、助手、候选、已配对主机与待确认请求；不返回私钥或 endpoint token |
| `POST /v1/manage/settings` | `name`、`network_enabled`、`discovery_enabled`、`listen`、`interface` |
| `POST /v1/manage/agent` | `endpoint`、`action`，必要时带真实 `session_id`；操作包括 `install`、`enable`、`disable`、`share`、`unshare` |
| `POST /v1/manage/network` | `action` 为 `invite`、`pair`、`accept` 或 `disconnect`；`pair` 使用 `invitation` 和可选 `address`；`accept` 的 `peer_id` 填待确认请求 ID，`disconnect` 的 `peer_id` 填 Hub ID |

常规状态更新通过本机 SSE 展示，不唤醒模型。选择错误的网卡、启动 socket 失败或运行中发生传输错误时，发现状态会显示为关闭并保留错误；应用重启后发现网卡不存在，不应让原有本机邮箱失效。

“安装”按钮调用仓库固定的受管技能安装能力，适用于 Codex、WorkBuddy 和 Claude。它不安装或验证全部原生 Client、Claude 插件或 Grok Routine；后续独立 Client、私有配置和真实会话绑定按[各 Client 说明](CLIENTS.md)完成。安装文件、已绑定、Client 已连接和原生能力已验证是不同状态。安装、发现、配对、探活和路由都不调用模型。禁用 endpoint 不代表已运行的原生任务被取消。

## 数据与验证范围

数据目录内新增 `network/identity.json`、`network/state.json` 和 `discovery.json`，分别保存私有主机身份、网络状态与发现偏好。不要将身份文件、邀请证明或私有配置复制进公开文档、仓库或日志。保留身份文件才能在重启后维持同一 Hub ID。

首次写入联邦消息会将本机追加日志 `state.jsonl` 的快照版本提升到 **4**。旧程序不能安全理解这些字段；升级前备份完整数据目录，需要回退时使用匹配版本的程序与完整备份，不能盲目把旧可执行文件指向升级后的目录。

离线测试使用临时目录、模拟原生 Client 和注入的发现 socket，覆盖协议解析、过期、启停、配对、目录、消息持久化、重放、防环及管理操作。开发验证可运行：

```text
go test ./internal/discovery ./internal/mesh ./internal/manager ./internal/app
node --test internal/app/web/dashboard.test.cjs
```

这些测试没有启动真实局域网发现，也不调用模型。实际两台电脑、不同网卡、防火墙、组播策略、休眠恢复与原生助手执行仍需在获授权的目标环境单独验收。既有本机原生验收不自动等同于跨机验收。
