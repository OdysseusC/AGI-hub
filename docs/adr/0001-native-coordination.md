# 技能驱动对等协作，Hub 保持消息边车

用户从任意已接入的原生助手发起工作，各助手的协作技能按需委派、转交和处理关联回复，最终成果返回最初用户输入的会话。Hub 只保存接入目录、用户允许的互通范围、持久消息、投递证据、去重及基础限额，不引入中央团队计划、依赖图或独立智能主持人；协作 ID 和固定原入口足以关联多跳消息。这个选择保留灵活的原生入口，代价是业务分工、汇总和质量判断由技能与助手承担，消息可靠性不能被宣传为整个目标的完成保证。

技能与 Hub 同步维护：成员变化刷新动态目录，协作规则变化才更新受管技能；用户可在任意已接入入口发现新成员，不需要每次接入都重写所有提示词或唤醒模型。

本提案替换此前的集中团队调度建议，尚未改变运行协议。详见 [精简协作设计](../TEAM-ORCHESTRATION.md)。
