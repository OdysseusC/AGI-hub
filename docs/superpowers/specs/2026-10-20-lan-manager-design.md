# 局域网 Hub 与本机管理页

本设计依据用户已确认的范围：每台电脑一个 Hub，稳定主机身份与本机 endpoint 共同寻址；显式开启自发现；长连接、基本中继、可靠投递；简单的安装和主机/助手列表。采用独立功能分支与 PR，不自动合并，不改变现有本机安装。

## 边界

Hub 仍是定址消息管道，不选择协作者、不生成业务回复、不调用模型。原生 Client 继续连接本机 loopback；局域网传输使用独立监听器和独立身份。旧 Task/Report 保持本机兼容，新跨机通信用邮箱消息。安装、发现、配对、探活、路由和离线测试均不调用助手模型。

## 身份、发现、配对

为安装生成并持久保存主机密钥与稳定 Hub ID，显示名可修改，IP 变化不改变身份。同名 endpoint 用 `hub-id/endpoint-id` 区分；会话 ID 仍只在目的地本机绑定。

局域网通信与组播发现分别由用户显式启用，默认关闭。发现只在选定的局域网接口公告 Hub ID、名称、地址、协议版本；第一版使用 IPv4 mDNS/DNS-SD `_agihub._tcp.local.`，所选接口必须具有 IPv4 地址，服务记录支持 A/AAAA。支持手动数字 LAN 地址与邀请配对，地址覆盖只改变连接位置，保留邀请中的公钥和身份校验。组播发现不传凭据、会话记录或消息正文，不自动建立信任。关闭发现不撤销已有配对或断开已授权连接。

首次配对使用短期邀请并经双方确认，持久固定对方公钥身份；首次配对要求直接连通，不能经陌生中继建立信任。目录只公布明确共享的本机助手。发现、已配对、在线、经中继可达和离线分别展示；路由可达不能替代配对授权，信任不自动传递。A 和 C 即使之后经 B 中继，也须先完成彼此配对。

## 传输与可靠性

已配对 Hub 使用 TLS 1.3 与 HTTP keep-alive 复用长连接，传递目录、路由和消息。转发包包含稳定消息 ID、来源/目的 Hub、端点、关联、期限和有限跳数。消息身份必须端到端验证，中继不能伪造来源、扩大权限或改写正文。目的 Hub 仍检查本机接收绑定与共享范围。

第一版优先已有可用直连，必要时通过有效邻居公告执行广度优先搜索，选择较短中继路径；路线包含路径防环和过期处理，路径/已访问节点按 `maxHops = 8` 限制。不实现延迟自适应、复杂权重学习或频繁拓扑调整。高频通信可复用直连；任何自动连接都需满足既有配对。

待发送记录持久保存后才确认提交。断线后以相同消息 ID 重传，目的端相同 ID/相同内容幂等，不同内容拒绝。网络接收 ACK 只代表目的 Hub 持久保存，不等于原生会话已消费或业务完成；原生投递不确定时沿用既有保守规则。

邮箱联邦协议 1 每个关联固定两个 endpoint，使用 `<64位小写十六进制Hub-ID>/<endpoint>` 寻址，提交返回规范 `lan-…` ID。总消息额度固定分为发起方 `ceil(max_messages/2)` 与另一方 `floor(max_messages/2)`，不能复制或借用；联系第三个 endpoint 需要独立且已获授权的关联，不能新建关联绕过耗尽限制。取消关联只作用于本机，已进入 mesh 队列或已发出的消息可能继续。首次联邦写入将日志快照升级为 v4，不能盲目降级旧程序。

第一版跨机共享消息和目录。文件引用保留来源主机与工作区归属，不能把远端本机路径当成本机路径，不默认同步文件。

## 管理页

复用 Hub 的本机网页和 SSE。顶栏展示本机名称、网络/发现开关与在线数量；主体分为本机 agents、其他 Hub（可展开其可见 agents）、最近消息。数量明确为本机视角，不伪装全网一致目录。常规页面更新不唤醒模型。

本机 agent 操作包括安装受管技能、配置/绑定引导、启用/停用与明确共享。安装仅调用仓库内固定安装能力，不接受任意 shell。Codex/WorkBuddy/Claude 可安装受管技能；独立原生 Client、Claude 插件与 Grok Routine 等宿主特定步骤须如实展示为后续配置，不把文件安装冒充已接通。状态区分文件已安装、待绑定、已配置、连接状态待核实和已验证。禁用不意味着取消已运行原生任务。

网络操作包括邀请、提交配对请求、接受配对、断开及手动地址。界面不显示私有配置和 token，管理接口只留在 loopback。

操作、接口和数据迁移说明见 [局域网 Hub 与本机管理](../../LAN.md)。

## 验收

离线测试涵盖：默认零 LAN 流量、开启/关闭发现、发现过期与协议解析、主机身份重启稳定、陌生节点拒绝、配对确认与过期邀请、同名助手分流、三 Hub 中继、防环、断线重连、重启恢复、重复消息、同 ID 篡改、权限/解绑变化、安装幂等与本机 API 校验。用临时目录和模拟原生 Client 验证跨 Hub 消息进出本机邮箱；浏览器验证树列表与操作错误状态。

真实两台电脑、不同网卡/组播策略及原生助手行为仍需用户环境验收。测试与 PR 明确区分这些范围。未经用户决定不部署到既有生产安装、不发真实 Claude 请求、不自动合并 PR。
