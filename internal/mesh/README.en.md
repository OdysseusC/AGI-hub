# LAN mesh transport boundaries

[简体中文](README.md) | [English](README.en.md)

This package handles host identity, explicitly confirmed pairing, directories, and addressed messages. It never invokes models, creates native sessions, or executes message contents.

- `New` creates and saves an Ed25519 identity. The Hub ID is the public key's SHA-256 digest as 64 lowercase hexadecimal characters. `Start` opens no network listener by default; `Configure(Enabled: true)` is required.
- Listener addresses may be numeric LAN, loopback, or wildcard addresses. Advertised, invitation, and manual connection addresses must be numeric private, link-local, or loopback addresses with a valid port. Public hostnames and IP addresses are rejected. A wildcard listener requires an explicit reachable `AdvertiseAddr` before pairing.
- Invitations expire within 10 minutes. The requester confirms locally by calling `RequestPair`/`RequestPairAt`; the inviter confirms through `AcceptPair`. Initial pairing requires direct reachability between both Hubs; relay routing cannot replace initial identity confirmation. Invitation codes contain a one-use secret returned only by the invitation API, never in `Snapshot`.
- `RequestPairAt` overrides the connection address only, preserving the invitation's Hub ID, public key, and invitation proof. Discovered address changes for an existing paired Hub are saved only after a TLS connection verifies the original pinned public key. Discovery never establishes trust.
- Transport uses TLS 1.3, mutual public-key identity, and reused HTTP keep-alive connections. Encryption applies to each hop; relays can read forwarded payloads. Origin messages and destination receipts are separately signed to provide end-to-end identity and integrity, not end-to-end payload encryption.
- Directories publish only the intersection of `Config.Exports` and `LocalAgents()`. Each host signs its own short-lived declaration. Visibility, reachability, and pairing are separate states; origin and destination must still explicitly trust one another.
- Routing prefers a usable direct connection, then the fewest hops in valid directories. Each hop checks visited hosts, expiry, and a maximum of eight hosts. Adjacent transport connections must be paired locally. Failed peers use a 1–30 second reconnect backoff; retries preserve message IDs.
- `Send` persists the original message before returning `queued` or `received`. Retries recheck local sharing; revoking sharing or pairing stops unsent messages. Destinations also recheck pairing, exports, and local agent availability on reception.
- `Options.Receive` must be idempotent by `(FromHub, ID)`, durably accept before returning `nil`, and honor its context. Mesh saves pending input before the callback, persists deduplication after success, and only then signs an ACK. A crash between the callback and the final write can replay identical input, so the callback itself must be idempotent. This ACK **does not mean native session consumption or task execution completed**.
- Identical content with the same origin/ID can be retransmitted safely; conflicting content is rejected. Successful or expired records retain hashes and status tombstones while clearing payloads, so history does not consume active queue capacity. Expiry without a successful receiver callback remains a failure and cannot produce a successful ACK; conflicting ID reuse remains forbidden after restart.
- Limits are 256 KiB payloads, 512 KiB frames, 1,000 active outgoing and incoming records, 128 peers/directory nodes, 64 concurrently accepted TCP/TLS connections, and explicit request, read/write, and shutdown timeouts. Terminal deduplication tombstones remain in the private state directory; observed message IDs are never automatically reused.
- `Disconnect` revokes this Hub's trust in a peer. Disabling discovery does not invoke it or alter existing pairing.

`identity.json` and `state.json` contain private runtime data and must never be committed. Writes use same-directory temporary files, synchronization, and replacement. POSIX permissions are private; Windows also relies on the installation directory's user ACL. Failures preserve pending transmission/reception state and do not repeat native side effects.

Offline tests use temporary directories and real TLS connections on loopback, covering three-Hub relay, deduplication, signatures, export revocation, address changes, restart recovery, and listener failures. Real cross-machine, firewall, selected-interface, and native-assistant behavior require separate acceptance testing. The current Windows environment has no usable CGO compiler, so `go test -race` cannot run; regular Go tests and `go vet` can run.
