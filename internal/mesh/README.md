# LAN mesh 传输边界

[简体中文](README.md) | [English](README.en.md)

本包只处理主机身份、用户确认的配对、目录和定址消息。不会调用模型、创建原生会话或执行消息正文。

- `New` 生成并保存 Ed25519 身份；Hub ID 是公钥 SHA-256 的小写 64 位十六进制值。`Start` 默认不开网络，必须显式 `Configure(Enabled: true)`。
- 监听地址可以是数字形式的 LAN 地址、loopback 或通配地址；公告、邀请和手动连接地址必须是数字形式的 private、link-local 或 loopback 地址，端口必须有效。不解析公网域名，也不接受公网 IP。使用通配监听时，须显式设置可到达的 `AdvertiseAddr` 才能配对。
- 邀请最多有效 10 分钟。请求方调用 `RequestPair`/`RequestPairAt` 表示本地确认；邀请方调用 `AcceptPair` 完成另一侧确认。首次配对要求双方直接可达；中继不能替代初次身份确认。邀请码含一次性秘密，只通过邀请 API 返回，不进入 `Snapshot`。
- `RequestPairAt` 只覆盖连接地址，仍固定邀请内的 Hub ID、公钥和邀请证明。已配对节点的发现地址变化也必须通过原公钥的 TLS 连接验证后才会保存；发现信息不建立信任。
- 传输使用 TLS 1.3、双向公钥身份和复用的 HTTP keep-alive 连接。加密覆盖每一跳；转发节点能读取转发正文。来源消息及目的端回执分别签名，提供端到端身份与完整性验证，并非正文的端到端加密。
- 目录只公布 `Config.Exports` 与 `LocalAgents()` 的交集。每个目录声明由其主机签名并短期过期。可见、可路由与已配对是不同状态；来源和目的地仍必须彼此明确配对。
- 路由优先可用直连，其次采用有效目录中的最少跳数。每次转发检查已访问路径、期限和最多 8 个主机；邻接传输只能经过当前节点自己的已配对连接。节点失败后采用 1–30 秒退避，恢复时保持原消息 ID。
- `Send` 先持久保存原消息，再返回 `queued` 或 `received`。源端重试时重新检查本地共享状态，撤销共享或配对会停止尚未送出的消息。目的端每次接收也重新检查配对、共享与本地 agent 可用性。
- `Options.Receive` 必须按 `(FromHub, ID)` 幂等、在返回 `nil` 前完成持久接收，并遵守传入上下文。mesh 在回调前保存 pending 输入，回调成功后保存去重状态，之后才能签发 ACK。崩溃发生在回调与去重落盘之间时，会再次调用相同输入，因此回调自身也必须幂等。该 ACK **不表示原生会话消费或任务执行完成**。
- 相同来源/ID 与相同内容可安全重送；内容不同会拒绝。成功或过期记录保留哈希与状态墓碑，清除正文，避免历史占用活动队列。过期但接收回调未成功的记录仍为失败，不能获得成功 ACK；重启后也不允许复用其 ID 改写内容。
- 上限为 256 KiB 正文、512 KiB 帧、1,000 条活动发送和接收记录、128 个对端/目录节点、64 个同时接入的 TCP/TLS 连接，以及明确的请求、读写与关闭超时。终态去重墓碑保留在私有状态目录；不自动重用已见消息 ID。
- `Disconnect` 撤销本机对该 Hub 的配对授权。关闭发现不调用它，也不影响已有配对。

`identity.json` 和 `state.json` 是私有运行数据，不得提交版本库。文件使用同目录临时写入、同步及替换；POSIX 权限为私有模式，Windows 同时依赖安装目录的用户 ACL。失败时保留待发送/待接收状态，不重做原生副作用。

离线验证使用临时目录和 loopback 上的真实 TLS 连接，覆盖三 Hub 中继、去重、签名、共享撤销、地址变化、重启恢复与监听失败。真实跨机器、防火墙、选定网卡与原生助手行为仍需另行验收。当前 Windows 环境无可用 CGO 编译器，`go test -race` 不可运行；常规 Go 测试与 `go vet` 可运行。
